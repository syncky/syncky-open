# Transport message table

`messages.json` is generated by the Syncky core's protocol artifact generator. Change the protocol definitions and regenerate the artifacts together; never edit the table by hand. Its structural schema is [`schemas/messages.schema.json`](schemas/messages.schema.json). The generation checks compare every current marker enum, actual message-to-marker mapping, kind, limit, canonical field order and AAD against the implementation and existing vectors. Generation is deterministic and existing vector bytes remain unchanged.

The table is the transport contract for the thin agent. It is published alongside the schemas and vectors and bundled with the signed skill. The phone and relay retain their own implementations and do not load this file.

## Format

`schema_version` identifies the table format; `protocol_version` identifies the envelope protocol. A consumer must support both before activating a table. Unsupported versions or AAD capabilities retain the last good table and expose protocol incompatibility; never guess at cryptographic rules.

| Field | Meaning |
| --- | --- |
| `kinds` | Supported encrypted envelope kinds: `data` and `control`; relay plaintext system events are separate metadata |
| `messages` | Inner `type` → `kind`, optional required `marker: {field, value}`, `max_envelope_bytes`, and applicable inner size information |
| `default` | Rule for an unlisted inner type: unmarked `control`, with the control envelope cap |
| `markers` | Supported visible marker fields and their values; every value has exactly one matching message entry |
| `limits` | Serialized envelope caps, recipient count, member-id length, marker exclusivity and crypto byte sizes |
| `aad` | Base template, per-kind suffixes, marker suffix template and order, and the two authenticated uses |
| `canonical` | Ordered submitted-envelope and recipient fields; omit optional marker fields when absent |

Envelope limits count UTF-8 bytes of the complete serialized submitted envelope, including base64 and recipients, excluding delivery metadata such as `seq`. Data envelopes allow 262144 bytes; controls allow 4096. Diagnostics additionally have a 180000-byte `max_inner_bytes` cap on UTF-8 inner JSON. Sync's 180000-byte `target_inner_bytes` is a sender chunk target, not a receiver-wide inner limit. No inner cap is implied when `max_inner_bytes` is absent.

Every named control and all three data types (`sync`, `commands`, `diagnostics`) are listed. The `default` rule permits feature extension without a transport type registry. It does not define feature schemas, permissions, consent, units, command policy or lifecycle handling.

## Markers, bytes and consumers

For a listed marked type, require exactly its declared marker and kind after authentication. For an unmarked or unlisted type, require no marker. At most one supported marker field may be present. Reject missing required markers, extra, unknown, null, malformed, conflicting and mismatched markers before acting on the inner message. Never strip a marker or fall back to legacy AAD after authentication failure.

Construct AAD as UTF-8: substitute the hub id, message id and sender into `aad.base`, append the entry for the envelope's kind in `aad.kind_suffixes`, then append each present marker through `aad.marker_template` in `aad.marker_order`. Use those same bytes for both HPKE Auth CEK wrapping and payload AEAD. The unmarked data suffix is empty; control adds `|control`. Marker suffix order is `diagnostics`, then `access`, while canonical envelope JSON places `access` before `diagnostics`. Mutual exclusion permits only one marker suffix on a valid envelope. An exact persisted retry keeps its original sealed bytes.

The thin transport uses this table for sealing, envelope shape/size checks and authenticated marker/type/kind matching. Receiving still preserves authentic JSON objects with a string `type`, including unknown fields and types, without feature-schema validation. Optional send validation uses available local schemas. The schemas and signed skill describe feature behavior; the table grants no permission to send writes or requests. See the [protocol file inventory](README.md#files) for the other artifacts and consumers.
